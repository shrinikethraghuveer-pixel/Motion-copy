# Security Policy

## Reporting a vulnerability

Please do not disclose vulnerabilities in public GitHub issues, discussions, or pull requests.

Use GitHub’s **private vulnerability reporting** for this repository: open the repository’s **Security** tab and select **Report a vulnerability**. This sends the report privately to the maintainers. Repository administrators should enable private vulnerability reporting in the repository’s security settings before publication.

If private vulnerability reporting is unavailable, contact the maintainers through a private channel associated with the repository and ask for a secure reporting route. Do not include exploit details in a public message. This repository currently does not publish a dedicated security email address.

When reporting, include the affected component or file, impact, steps to reproduce, and any suggested mitigation. Please avoid accessing or modifying other users’ data, and stop testing once the issue is confirmed.

## Response

Maintainers will acknowledge reports, investigate and coordinate a fix, and work with the reporter on a responsible disclosure timeline. Please allow time for remediation before public disclosure.

## Supported versions

Security fixes are made against the latest version on the default branch. No older release support policy is currently defined.
